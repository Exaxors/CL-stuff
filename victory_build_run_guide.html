⚠ GPU DRIVER RESET (TDR) & UNVERIFIED FORK RISK

Expect Driver Resets Past the Menu: Entering the 3D open world on experimental builds frequently triggers Windows Timeout Detection and Recovery (TDR), temporarily blacking out your monitors and resetting the NVIDIA display driver. The latest runs did not crash, but it is not ruled out.

Inspect Before Building: Community forks move rapidly and contain experimental, unreviewed code. Always review the source code before compiling and never run precompiled .exe binaries from untrusted links. There is no official installer.

RAM & VRAM: A run in the world takes about 33 GB of Windows commit (RAM plus paging file) and about 10 GB of video memory. Check Committed under Task Manager → Performance → Memory. If crashes.log reports Windows error 1455, close other applications or increase the Windows paging file size, then retry.

System & Environment Requirements
Baseline Setup & Tooling
What your machine and workspace need before compiling or running the runtime.

Windows 10 / 11 (64-bit) + AVX2 CPU
Requires a modern 64-bit Windows environment on an AVX2-capable processor.
D3D12 SM 6.6 + Mesh Shaders RTX 5090 Ready
Needs a Direct3D 12 GPU with Shader Model 6.6 and Mesh Shader support; your RTX 5090 clears this easily.

Build & Run Walkthrough
01
Clone the Fork Repository
Pick a fork tab or dropdown option to update the clone command below.

Selected: DexNom/VIctory — Community fork under active experimentation.

POWERSHELL 
git clone https://github.com/DexNom/VIctory.git
cd VIctory
CHECKPOINT: The repository clones cleanly and dir inside the folder lists Cargo.toml and victory.example.toml.
02
Install Safety Commit Hook
Enable xtask hooks so binaries or game assets are never accidentally staged in Git.
POWERSHELL 
cargo xtask install-hooks
CHECKPOINT: Cargo finishes building xtask and installs the pre-commit hook cleanly.
03
Create & Configure victory.toml
Copy the example configuration and point it at your external unpacked game directory.
POWERSHELL 
copy victory.example.toml victory.toml
notepad victory.toml
# Save victory.toml with your external game folder path, then validate:
cargo run -p victory -- config
CHECKPOINT: cargo run -p victory -- config prints resolved paths with zero missing-directory errors. Keep game files outside the VIctory directory.
04
Run Workspace Unit Tests
Confirm the Rust toolchain, shader translation crates, and loader modules compile before building.
POWERSHELL 
cargo test --workspace
CHECKPOINT: Workspace tests complete with test result: ok and no compilation failures.
05
Compile the Binary
Build the standard release binary or switch to the diagnostics profile for crash telemetry.
Build Profile Mode
Switch to Diagnostics if you want extra telemetry when troubleshooting GPU resets.
POWERSHELL · RELEASE PROFILE 
cargo build --release -p victory
CHECKPOINT: target\release\victory.exe is produced without linker errors.
06
Pre-Translate Shaders & Launch
Translate shaders first to warm up the cache, then start the runtime executable.
Optional Launch Flags & Environment Variables

Explanation: The flags below are appended to victory.exe. By default, victory.exe looks for the game path in your victory.toml (from Step 3). If you haven't configured the .toml yet, or want to point to a different directory, enable the --GamePath flag and edit the path in the command below.

POWERSHELL 
.\target\release\victory.exe translate --cache --pipelines "D:\My Games\Series X\shaders.rpf" "D:\My Games\Series X\game_scarlett_master.exe" "D:\My Games\Series X\XboxBvhBuilder.dll" "D:\My Games\Series X\amd_fidelityfx_upscaler_xbox.dll"
.\target\release\victory.exe run --execute "D:\My Games\Series X\game_scarlett_master.exe"
CHECKPOINT: The window opens, plays boot/intro videos around ~30 FPS, and reaches the start menu. Loading into the world takes about a minute; the intro cutscene plays, then the prologue starts. (Note: The current build runs at about 1 FPS in the world, with some missing ray-traced shadows.)
